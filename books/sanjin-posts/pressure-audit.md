# 阶段 4 压力审计

## 审计方式

本轮采用主流程结构化审计与语义抽样复核（资源受限 fallback），未把测试预期答案直接提供给被测 skill。重点检查触发描述是否具体、三类测试是否齐全、同书兄弟 skill 是否作为诱饵、以及边界是否能阻止过度调用。

## 结果

- skills：28/28
- 每个 `test-prompts.json`：6 条，可解析
- 每个 skill：3 条 `should_trigger`、2 条 `should_not_trigger`、1 条 `edge_case`
- 同书兄弟 skill 诱饵：28/28 至少 1 条
- R/I/A1/A2/E/B 六段：28/28
- 原文引用：抽查及 extractor 报告均 ≤150 字
- 结构化通过率：28/28（100%）

## 重点边界复核

1. 机会类 skill 均把“已有资产/真实需求/最小验证”写入触发条件，避免因单纯追热点而调用。
2. 内容类 skill 将对标、盲测、控制变量和内容质量区分开，诱饵分别指向兄弟 skill。
3. AI 类 skill 明确上下文、人工校验、原创和自动化前置条件，避免把任意写作请求都激活。
4. 增长类 skill 将咨询质量、成交和利润置于点赞/点击之上，并保留用户兴趣与合规边界。
5. 风险类 skill 对健康、权限、版权、授权和不可撤销动作设置判停条件。

## 说明

本报告的 100% 是结构与语义边界审计结果，不等同于在宿主 agent 上运行后的线上召回率。每个 skill 目录已保留 darwin 兼容的测试集，后续可用 darwin-skill 做独立盲测与回炉。
