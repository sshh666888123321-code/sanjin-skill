# 产品分层与持续更新交付

## R — 原文 (Reading)

> 后来我建议她调整思路，只做“考研英语作文模板+批改服务”，把重点放到服务上，定价99元，现在一个月能赚过万。
>
> — 叁斤，015｜新手怎么做好小红书虚拟电商？原创虚拟产品全面复盘

## I — 方法论骨架 (Interpretation)

不要把全部价值押在一份静态资料或一次性高价产品上。
先设计一个自己当前能负责交付的低价、窄结果版本，获得真实购买和使用反馈。
再按用户阶段、问题复杂度和交付深度分层：资料、模板、更新、批改、社群或陪跑。
把反馈、更新频率和服务边界写进产品承诺，而不是售后临时补洞。
只有低层版本可交付且有需求证据，才增加价格和服务深度。

## A1 — 书中的应用 (Past Application)

### 案例 1: 考研资料升级模板加批改
- **问题**: 泛考研资料同质化，低价销售难以差异化。
- **方法论的使用**: 收窄到英语作文模板，并加入人工批改服务。
- **结论**: 具体结果和服务交付比大而全资料更有价值。
- **结果**: 定价 99 元，案例中月收入超过 1 万元。

### 案例 2: 十条内容先卖知识库
- **问题**: 不确定知识产品是否有人买。
- **方法论的使用**: 先用十条内容标注更新，边卖边做，再根据用户阶段提供更深服务。
- **结论**: 购买反馈可以反向决定产品层级。
- **结果**: 形成由低价内容到社群/服务的产品梯度。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户有资料或经验，准备做一个完整高价课程/产品。
2. 低价资料销量有但利润低，想增加服务和结果交付。
3. 用户想建立持续更新、批改、社群或陪跑的升级路径。

### 语言信号 (用户的话里出现这些就应激活)

- “资料包怎么升级成产品 / how should I tier this offer?”
- “先卖什么版本，再做高价服务？”
- “如何让知识产品持续更新而不是一次性交付？”

### 与相邻 skill 的区分

- 与 `minimum-viable-loop` 的区别：本 skill 设计产品层级与持续交付；后者验证整个业务闭环能否跑通。
- 与 `reverse-funnel-scaling` 的区别：本 skill 分用户和交付深度；后者分扩张人群层级。

## E — 可执行步骤 (Execution)

1. **定义窄结果低层产品**：写清目标用户、一个具体结果、交付材料和自己能承担的时间；完成标准是可在短周期交付。
2. **先卖并收反馈**：用内容或小范围销售验证购买、使用和问题；若无人购买或无法交付，回炉结果定义，不开发高层产品。
3. **按深度分层**：将更新、批改、社群、陪跑等拆成增量价值，明确价格、频率和边界；完成标准是每层都有独立交付承诺。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 产品结果、目标用户和交付能力完全未定义。
- 用户做的是一次性明确范围的定制服务，不需要产品梯度。

### 作者在书中警告的失败模式

- 只卖泛资料，缺少具体结果和难以替代的服务。
- 先制作大而全课程，尚未验证购买和交付。

### 作者的盲点 / 时代局限

- 价格和用户支付意愿受平台、赛道和时点影响，案例定价不能直接照搬。

### 容易混淆的邻近方法论

- 分层不是强行制造多个 SKU；每一层必须对应真实新增结果或交付责任。
