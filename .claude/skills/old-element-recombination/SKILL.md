# 旧元素重组创新法

## R — 原文 (Reading)

> 第一步：拆解，把你做的事拆到基本事实层面。第二步：清空，暂时忘掉「别人怎么做」。第三步：重组，把你的旧元素和眼前的新元素排列组合。
>
> — 叁斤，002｜踩中5次风口，赚了100w+，万字拆解

## I — 方法论骨架 (Interpretation)

把“创新”先还原成资源盘点，而不是凭空发明。
先把已有业务拆成客户、问题、内容、能力、交付和渠道等元素。
暂时放下同行的表面做法，避免把旧方案当成唯一答案。
再观察新平台或新技术真正新增了什么条件。
把旧元素与新条件重新排列，优先寻找低成本可测试的组合。
最后用一个小内容、样品或首单验证组合，而不是直接扩大投入。

## A1 — 书中的应用 (Past Application)

### 案例 1: 好物分享矩阵
- **问题**: 新手想进入小红书内容变现窗口。
- **方法论的使用**: 先把已有的选品、内容和账号能力复制到多个账号。
- **结论**: 旧内容能力与新平台窗口可以重组为矩阵。
- **结果**: 高峰期一人同时运营 20 多个账号，月广告收入数万元；窗口收窄后收缩资产。

### 案例 2: 旅游营销迁移到婚摄
- **问题**: 婚摄需要可复制的获客组合。
- **方法论的使用**: 将境外游已验证的品牌号、关键词、内容和投放元素按婚摄决策路径重新组合。
- **结论**: 可迁移的是底层组合，不是原行业的表面内容。
- **结果**: 该组合在婚摄场景获得可用反馈。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 新工具/平台出现，用户有旧客户或旧内容，但不知道怎么迁移。
2. 用户说“我不想从零做，手上的资源能不能变成新产品”。
3. 用户正在比较多个热点，却还没有形成可验证的方案。

### 语言信号 (用户的话里出现这些就应激活)

- “把现有业务迁移到新平台 / reuse existing assets”
- “有什么旧资源可以重组？”
- “不要照抄竞品，怎么做差异化？”

### 与相邻 skill 的区分

- 与 `ai-asset-amplification` 的区别：本 skill 先重组跨场景元素；后者专门判断 AI 是否放大已有资产。
- 与 `minimum-viable-loop` 的区别：本 skill 生成组合假设；后者负责让已选假设跑过最小闭环。

## E — 可执行步骤 (Execution)

1. **拆出旧元素**：列出已有客户、问题、内容、能力、交付、渠道和可用数据；完成标准是每项都有具体例子。
2. **描述新条件并重组**：写出新平台/技术提供的新增约束或机会，生成至少 3 个旧元素×新条件组合；若只有模糊热点词，先停止并补事实。
3. **做低成本验证**：选成本最低且可撤销的一组，发布一个内容、样品或服务测试，记录触达、咨询、成交和交付结果。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户已有明确执行方案，只需要拆任务或排期。
- 组合依赖搬运、伪造体验、操纵互动或规避平台规则。

### 作者在书中警告的失败模式

- 直接复制别人的项目、话术或拍摄参数，忽略新场景的环境和交付约束。
- 只因热点看起来热就投入，未验证需求和自身资产匹配。

### 作者的盲点 / 时代局限

- 帖子中的平台窗口和收益是当时样本，不能当作当前回报承诺；必须重新验证规则、成本和用户需求。

### 容易混淆的邻近方法论

- “跨平台复制”不是照搬界面，而是重新验证底层需求和交付。
