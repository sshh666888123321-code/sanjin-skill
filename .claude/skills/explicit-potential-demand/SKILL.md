# 显性需求与潜在需求双层设计

## R — 原文 (Reading)

> 需求一般分为「正在需求」和「潜在需求」。正在需求（刚需）：用户会主动搜索，目的明确。潜在需求（唤醒）：用户原本没意识到，但看到你的内容后被瞬间激发。
>
> — 叁斤，028｜关于小红书虚拟电商选品

## I — 方法论骨架 (Interpretation)

先判断用户是否已经用语言主动寻找解决方案。
若有明确搜索、比较或求购，内容应直接回答问题，减少绕路，并把答案连接到产品或服务。
若用户还没有问题意识，不能用搜索承接的写法硬塞产品。
此时要用可见的场景、前后对比或结果演示，让用户先看到“原来这里有损失/不便”。
两层需求的入口、内容承诺和转化指标不同，不能只用点赞统一判断。

## A1 — 书中的应用 (Past Application)

### 案例 1: 搜索型手册与好物内容
- **问题**: 用户主动搜索运营或产品解决方案。
- **方法论的使用**: 以明确关键词和问题为入口，直接给解决步骤，再承接手册或好物。
- **结论**: 这是显性需求，首屏应让用户确认“这正是我要解决的问题”。
- **结果**: 叁斤记录过不到 1000 粉卖出 800 份 39 元手册（c24）。

### 案例 2: 养生日历与解压玩具
- **问题**: 用户不会主动搜索一个日历或单一玩具。
- **方法论的使用**: 先展示养生场景或具体使用带来的变化，再让用户意识到产品用途。
- **结论**: 这是潜在需求，演示比关键词堆叠更重要。
- **结果**: 养生主题账号的日历售出 800 多单（c34）；单一解压玩具用场景内容唤醒购买（c59）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 同一个产品既可以做搜索承接，也可以做场景种草，不知道内容入口怎么选。
2. 用户说“没有人搜这个”“我该不该先教育市场”，需要区分搜索需求与唤醒需求。
3. 需要为新产品设计首屏、选题和转化指标。

### 语言信号

- “这个需求用户会主动搜吗？” / “Is this an explicit search intent?”
- “没人搜，但我觉得看了会想要。”
- “首屏应该直接回答，还是先做演示？”

### 与相邻 skill 的区分

- 与 `dual-route-demand-evidence` 的区别：本 skill 先判定需求入口；后者验证两条证据链是否同时成立。
- 与 `minimum-viable-loop` 的区别：本 skill 决定内容如何唤醒或承接；后者决定先用多小的闭环验证。

## E — 可执行步骤 (Execution)

1. **标注需求状态**：列出用户原话、搜索词、评论或演示反应，判为“正在需求”“潜在需求”或“不确定”。完成标准：每个判断都有至少一条可回溯证据。
2. **匹配内容入口**：正在需求用问题—答案—下一步；潜在需求用场景—痛点/结果—产品演示。完成标准：写出一条首屏承诺和一个对应指标。
3. **做小测试**：各发布一组低成本内容或一个可退换的最小版本，比较精准搜索/求购与演示后的主动兴趣。完成标准：记录入口、行动和转化，不把泛点赞当结论。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 已有明确成交漏斗，只需要定位哪个投放单元转化更好。
- 只是改写文案措辞，不需要判断需求入口。

### 作者在书中警告的失败模式

- 把所有内容都做成泛流量或把点赞当需求，导致有曝光却没有精准求购（p040、c38）。
- 只凭个人感觉开发产品，没有搜索、评论或演示反馈。

### 作者的盲点 / 时代局限

- 内容平台的搜索权重、推荐分发和用户疲劳会变化；不能把一次入口测试当成永久结论。

### 容易混淆的邻近方法论

- `dual-route-demand-evidence`、`minimum-viable-loop`。
