# 长期项目五项筛选与跨领域迁移

## R — 原文 (Reading)

> 1、我做过，并且已经有成绩了；2、已经有了自己独到的见解和方法论；3、方法论可以复制；4、与主业有关联；5、我喜欢这个行业或项目。
>
> — 叁斤，126｜从0到1的副业历程

## I — 方法论骨架 (Interpretation)

长期项目先过五项筛选：已有成绩、独到方法、可复制、与主业关联、长期喜欢。
它把“看起来赚钱”改成“我能否持续积累优势”的判断。
通过筛选后，不直接照搬别人的表面做法，而是提炼其他领域的底层结构。
再明确自己的身份、应用场景和交付对象，把学习内容改成可交付方法。
最后用一个具体项目取得结果，才算迁移完成。
若五项中关键证据缺失，先做小测试，不承诺长期投入。

## A1 — 书中的应用 (Past Application)

### 案例 1: 多项目分散后聚焦小红书
- **问题**: 同时尝试多个副业，每个项目只投入很少时间。
- **方法论的使用**: 回看已有经验、成绩和个人适配度，重新聚焦已有优势的小红书。
- **结论**: 长期积累需要集中执行密度。
- **结果**: 聚焦后店铺月销量达到 10 万元以上，并继续担任航海教练。

### 案例 2: 跨副业知识做课程
- **问题**: 需要把其他副业的有效经验变成自己的交付。
- **方法论的使用**: 吸收底层思路、明确身份、完善课程，再用具体项目验证。
- **结论**: 迁移链是学习—定位—产品化—实证。
- **结果**: 作者将小红书实操经验做成陪跑课程，售出二十多份、收入 2 万元以上。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户同时有多个项目，无法决定主攻方向。
2. 用户想把一个领域的经验迁移到新项目或知识产品。
3. 用户需要检查“喜欢”是否有成绩、方法和复制证据支撑。

### 语言信号 (用户的话里出现这些就应激活)

- “我该 all in 哪个副业？ / which project should I focus on?”
- “怎么把这个领域的经验迁移到另一个项目？”
- “我喜欢这个方向，但值得长期做吗？”

### 与相邻 skill 的区分

- 与 `old-element-recombination` 的区别：本 skill 先筛长期项目并迁移知识；后者针对新机会组合已有元素。
- 与 `act-problem-feedback-loop` 的区别：本 skill 选方向；后者在方向已选后用行动获取反馈。

## E — 可执行步骤 (Execution)

1. **五项评分**：对每个项目按成绩、独到方法、可复制、主业关联、喜欢程度写证据和缺口；完成标准是每项都有事实而非形容词。
2. **提炼可迁移结构**：从高分项目提取底层问题、用户、方法、交付和结果，写出新项目的对应关系；若只能复制表面内容，停止迁移。
3. **小项目实证**：把结构做成一个具体服务/内容/产品并交付，记录结果；只有产生真实反馈才增加长期投入。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户已有明确项目，只需排期或拆成原子任务。
- 目标只是追逐短期热点，且没有长期积累意愿。

### 作者在书中警告的失败模式

- 多项目并行导致每个方向都没有足够执行密度。
- 把别人成功的表面项目直接搬来，忽略自己的能力和耐受度。

### 作者的盲点 / 时代局限

- “喜欢”和“主业关联”是主观指标，需与现金流、时间和机会成本一起复核。

### 容易混淆的邻近方法论

- 知识迁移不是资料搬运；必须产出自己的方法并在真实项目中验证。
