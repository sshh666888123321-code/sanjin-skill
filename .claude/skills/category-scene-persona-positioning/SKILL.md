# 品类×场景×人设定位矩阵

## R — 原文 (Reading)

> 账号定位 = 赛道 X 用户 X 价值 X 人设 X 视觉。一个账号，包含运营赛道、目标用户、账号价值、人设和视觉。
>
> — 叁斤，081｜普通人做小红书

## I — 方法论骨架 (Interpretation)

定位不是一句兴趣口号，而是一个可选择、可表达、可被识别的坐标。
先把品类拆开，再把用户使用或消费场景列成第二个轴，形成具体组合。
对每个组合补齐目标用户、可提供的价值、人设和视觉表达。
删除自己无法持续产出、无法触达用户或无法交付的格子。
最后用少量内容验证用户是否理解你是谁、为什么关注你，而不是因短期粉丝上升就频繁切换。

## A1 — 书中的应用 (Past Application)

### 案例 1: 家居赛道能力不匹配
- **问题**: 只因家居广告报价高就进入赛道。
- **方法论的使用**: 忽略自身审美、空间和产品调性等能力条件。
- **结论**: 赛道热度和报价不能替代个人资源适配。
- **结果**: 涨到几千粉但接不到高价值广告，最终放弃（c39）。

### 案例 2: 租房改造定位扩散
- **问题**: 原定位持续加入不相关内容。
- **方法论的使用**: 没有保持品类、场景和用户预期的一致。
- **结论**: 定位漂移会让账号变成杂货铺。
- **结果**: 数据恶化并放弃账号（c40）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 想开始一个账号，但赛道选择来自别人赚钱的案例而非自身条件。
2. 用户、价值和内容主题都很泛，无法说清账号服务谁。
3. 已经有一个方向，却在多个主题间摇摆，担心定位漂移。

### 语言信号

- “我适合做什么赛道？” / “Which niche fits me?”
- “我的账号什么都能发，怎么收窄？”
- “别人这个赛道赚得多，我要不要跟？”

### 与相邻 skill 的区分

- 与 `monetization-backward-design` 的区别：本 skill先做定位矩阵；后者从成交结果倒推账号与产品。
- 与 `element-level-benchmarking-hotspot-lifecycle` 的区别：本 skill评估自身条件；后者拆外部样本的元素和热度阶段。

## E — 可执行步骤 (Execution)

1. **画品类×场景矩阵**：列出 3–5 个品类和 3–5 个真实使用场景。完成标准：每个格子都能写出一个具体内容问题。
2. **补五因子并筛选**：为候选格填写目标用户、价值、人设和视觉，检查技能、兴趣、时间、资源与产品。完成标准：保留 1–2 个自己能连续表达和交付的格子。
3. **最小定位测试**：围绕一个格子发布一组一致内容，询问用户是否能复述你的主题和价值。完成标准：用有效关注、咨询和内容反馈判断，不因一次低流量频繁换定位。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 定位已稳定，只需要对标一条笔记或优化单个选题。
- 产品、成交对象和结果已明确，重点是倒推变现路径。

### 作者在书中警告的失败模式

- 只看别人赚钱就跟进，忽略自己的能力与长期喜好（p075、p079）。
- 账号内容发成大杂烩，用户标签和预期失焦（c40）。

### 作者的盲点 / 时代局限

- 定位矩阵不能替代平台需求和商业验证；矩阵中的“适合”仍需用真实咨询和交付检验。
